# LAB 2 클록 분주 실험 전 레포트

## 1. 예상 상태와 분주 주기 계산
10분주(DIVISOR=10)를 기준으로 `count`, `divided`, `tick`의 예상 상태는 다음과 같습니다. 
* **count:** 0에서 시작하여 클록 에지마다 1씩 증가하고 `DIVISOR - 1` (9)에서 다시 0으로 초기화됩니다. 
* **divided:** `count`가 `DIVISOR/2 - 1` (4)에 도달하는 에지에서 1(High)이 되고, `DIVISOR - 1` (9)에서 0(Low)이 됩니다. 즉, 짝수 DIVISOR에서 High와 Low의 시간이 동일합니다.
* **tick:** `count`가 `DIVISOR - 1` (9)일 때만 1이 되는 단일 클록 폭의 신호입니다. 다른 순차 회로의 Enable 신호로 활용됩니다.
* **분주 주기:** 테스트벤치 기준 입력 클록 10ns의 10배인 100ns 주기를 갖습니다. 실제 보드(1 kHz 기준)의 경우 10분주의 주기는 10ms가 됩니다.

## 2. 파일별 역할 설명
* **RTL (clock_divider.v, input_frontend.v, lab2_clock_divider.v):** 클록을 분주하고, 스위치/버튼의 비동기 입력을 처리하며, 이들을 조합해 전체 논리 회로를 구현하는 설계 소스 파일입니다.
* **TB (tb_clock_divider.sv):** RTL 코어(분주기)에 가상의 인가 신호(clk, rst)를 주입하고, 설계된 기능(듀티, tick 발생 시점, 리셋 동작)이 올바른지 자가검사(self-checking)를 수행하는 테스트벤치 파일입니다.
* **simulation.json:** Icarus 시뮬레이터와 VS Code 확장이 컴파일하고 실행할 소스 및 테스트벤치 파일 경로, 시뮬레이션 Top 모듈을 선언하는 설정 파일입니다.
* **XDC (lab2_clock_divider.xdc):** 타깃 보드의 실제 핀 매핑(예: B6, K4)과 I/O 표준(LVCMOS33), 클록 주기(1 kHz) 등 하드웨어 물리적 제약조건을 Vivado에 전달하는 파일입니다.

## 3. 시뮬레이션 검사 로그 비교
`clock_divider.v` 코드의 `DIVISOR/2 - 1` 조건을 고의로 `DIVISOR/2`로 변경하여 발생한 오류와 이를 원복한 결과를 비교하였습니다.

| 상태 | 실행 결과 로그 | 분석 내용 |
| :--- | :--- | :--- |
| **정상 (수정 전)** | `LAB2_PASS clock_divider checks=129` | 30개의 클록 안에서 듀티, 위상, tick 횟수 및 리셋 검사 총 129개가 정상 통과되었습니다. |
| **변경 (오류 발생)** | `LAB2_FAIL minimum divisor duty time=16000` | 상승 에지 조건을 1 지연시킴으로써 `minimum divisor duty` 검증에서 기댓값과 불일치하여 16 ns 시점에 $fatal이 발생하고 시뮬레이션이 중단되었습니다. |
| **원복 (수정 후)** | `LAB2_PASS clock_divider checks=129` | 코드를 원래대로 복구한 뒤 다시 시뮬레이션하여 129개 검사가 모두 정상 통과함을 재확인했습니다. |

## 4. 파형 분석
> **[VaporView 파형 스크린샷](../../evidence/02/vscode/wave.png)**

* **듀티 및 tick 파형 분석:** 10분주의 경우 `divided`는 55 ns에서 처음 1이 되고 105 ns에 0이 되어, 50 ns (High) / 50 ns (Low)의 정확히 50% 듀티를 갖는 100 ns 주기 파형을 보입니다. `tick`은 95~105 ns 구간처럼 다음 상승 에지에서 Enable로 소비되기 직전에 단 한 번 1이 됩니다. 30클록 동안 정확히 3회 관찰되었습니다.
* **리셋 파형 분석:** 376 ns 시점에 `rst=1`이 인가되면, `tick`은 즉각 0으로 마스킹됩니다. 이어지는 385 ns 상승 에지에서 `count`와 `divided` 값이 리셋 조건에 의해 0으로 동기식 초기화되는 것을 확인했습니다. `rst=0`으로 돌아온 후 435 ns에서 `divided`가 다시 1로 상승하며 주기가 정상 재시작됩니다.

## 5. 보드 설정 및 LED 측정 계획
이 회로는 Combo II-DLD S75 보드를 사용하며, XDC를 통해 메인 클록을 1 kHz로 설정합니다 (주기 1ms). K4(리셋 버튼)와 N8, DIP 스위치 등을 이용하며, 동작 중 N8 버튼이나 DIP 스위치는 분주비를 변경하지 않습니다. 예상 동작과 측정 방법은 아래와 같습니다.
* **LED[0] (2분주):** 500 Hz 주파수로 동작하므로 육안 구분이 불가능합니다. 파형이나 오실로스코프 등 측정 장비로 확인해야 합니다.
* **LED[1] (10분주):** 100 Hz 주파수이므로 파형이나 측정 장비를 이용해 확인합니다.
* **LED[2] (50분주):** 20 Hz 주파수이므로 빠른 주기를 직접 혹은 측정 장비를 이용해 비교 관찰합니다.
* **LED[3] (1000분주):** 1 Hz 주파수(주기 1초)이므로 0.5초간 켜지고 0.5초간 꺼지는 것을 육안과 영상 촬영으로 직접 확인합니다.
* **LED[4] (tick):** 1000분주의 tick 출력으로, 1 ms 동안만 켜지므로 눈으로 식별하기 어렵습니다. 측정 장비나 파형을 통해 확인합니다.
